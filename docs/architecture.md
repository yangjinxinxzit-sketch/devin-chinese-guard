# 工作原理与维护边界

## 更新后的识别

检查器读取 Devin 的版本和构建编号，再从前端入口的实际 import 引用中查找语言模块。AST 分析同时要求可识别的 `translation` / `review` 命名空间、英语资源和语言列表。只有一个明确匹配时才准备补丁。

它不会执行客户端 bundle 来提取资源。英文基线以 SHA-256 指纹保存；本机新原文与基线一致时使用对应中文，原文变化或未知词条则尝试独立词典，并在无法匹配时保留英文。

## 写入和备份

补丁准备阶段会再次解析生成的 JavaScript，并校验资源键、占位符和富文本标签。提交前后核对文件内容，在每个版本的独立目录保存原件和哈希。提交异常时尝试恢复已写入的原件。

官方中文语言包只补充当前版本存在、占位符匹配、且尚未翻译的相关条目。已有中文不会被批量覆盖。

回退前必须匹配当前资源及备份哈希。回退会暂停自动维护；再次手动修复才恢复。备份不会跨版本盲目写回。

## 完整重启

磁盘文件修复不等于当前窗口已经运行新代码。状态检查比较修复时的应用主进程身份与当前主进程身份；旧记录则结合进程启动时间判断。

同一主进程中的窗口重载、扩展服务重启和周期检查，均不会消除待完整重启状态。无法核实进程身份时不报告重启完成。

## 显示层

显示层只修改既有文本节点和提示属性，不改应用的业务字符串或输入值。它包含聊天、Markdown、编辑器、终端及可编辑区域的排除规则；这些规则需要随官方布局变化重新验证。

## 本项目不发布的内容

客户端原始 bundle、全量英文资源、运行备份、缓存、会话、账号配置和日志均留在使用者本机。测试使用项目生成的夹具；真实客户端资源验证是可选的本机只读步骤。
